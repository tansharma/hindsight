Helper scripts

Using the helper scripts directly

The agent runs these for you during a review, but they also work on their own (S=hindsight/scripts, or wherever you installed the skill):

bash "$S/list_files.sh" --root path/to/project > files.txt          # the files a review would scan
bash "$S/list_files.sh" --root path/to/project --since main          # only files changed since main, plus their importers
python3 "$S/import_graph.py" --root path/to/project --files-from files.txt > graph.json
python3 "$S/render_output.py" --check --root path/to/project --goal "..." findings.json   # validate only
python3 "$S/render_output.py" --root path/to/project --goal "..." findings.json           # write inHindsight.md/.json
python3 "$S/set_status.py" --root path/to/project --id H-004 --status resolved --note "..." [--commit <sha>]   # mark a finding
python3 "$S/rollup.py" --roots path/to/app path/to/api --out rollup.md   # one page across several projects
python3 "$S/export_tasks.py" --root path/to/project --format markdown --target pending.md   # open findings as tasks
python3 "$S/export_tasks.py" --root path/to/project --format gh > issues.sh   # gh issue commands, not run

export_tasks.py turns a review's open findings into tasks. With --format markdown it keeps a ## Hindsight section in the target file, one checkbox task per finding with its id, its prompt and how to tell it's done. Running it again updates each task in place by its id instead of adding duplicates, keeps your ticks and anything you wrote outside its tasks, and marks tasks for findings that are no longer open as closed. With --format gh it prints gh issue create commands for you to review and run; it never runs them, and finding text is quoted so the shell can't interpret it.

rollup.py summarizes the reviews already written in several projects: for each one, a table with the health score, open, resolved and won't-fix findings, the review date and its age in days, and a trend line across its archived reviews. A review more than 60 days old is flagged (change it with --stale-days). It reads only the saved inHindsight.json files and hindsight-history/, with no model and no network, and notes rather than fails on missing or unreadable files.

set_status.py records that you resolved, partly resolved, or decided not to fix (wontfix) a finding. It updates inHindsight.json and rewrites inHindsight.md in place with a status badge beside the finding's title; nothing is archived and no finding is renumbered. The next review treats the status as a claim to verify against the code, not as proof.

render_output.py --check exits 0 when a findings document is clean, 2 when it has warnings (unverifiable evidence, an unaddressed area, a re-run that doesn't account for the previous review), and 1 when it can't be rendered. A real render moves any previous review into hindsight-history/ first. Script internals are documented in hindsight/references/scripts.md.
